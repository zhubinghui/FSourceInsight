### MySQL首次失败为何没有绕过

`expire_all()`清ORM缓存但保留MySQL REPEATABLE READ事务快照。新引擎拥有独立事务，测试旧快照看不到已提交Article。真正候选复现同样NoResultFound；边界probe显示`success / no_change / fresh_rows=1 / caller_rows=0`。

修正两项新测试为新观察事务（`session.remove()`），包括回滚负例，保留状态、行数、JSON、ID等全部断言。**没有修改引擎或放宽隔离级别**，引擎也不会提交调用者Session。临时probe只存在测试副本，最终由正式测试替换。

其他偏差：首次git fetch工具超时、未跟踪schema末尾空行、Docker inspect缺User字段、HTTP脚本误POST只读manage返回405，均先记录再调整。manage改用实际GET路由后完整公网smoke通过，不修改业务路由。

## 已上线的范围与接下来任务

M1是确定性底座：契约、SafeFetch、执行/回放、质量门禁、手工CLI、标记及下游保护。**不是整个Agent自动流程已经上线**。旧基础RSS/HTML使用SafeFetch；新引擎尚未自动接管registry/Celery，15个自定义源及startup_discovery未全迁移。不因robots/许可失败退回不安全直连。

1. **M2（优先）**：schema/profile版本与证据，人工审批/回滚，接入日常调度；lease/fencing、outbox与消费幂等，统一next_due时区规则。
2. **M3**：硬预算预留/结算，有界学习与恢复，留出样本验证，独立学习队列；先候选、后人工发布。
3. **M4**：无业务凭据的隔离浏览器、子请求/资源门禁，代表来源对比和渐进迁移；不绕登录/付费墙/验证码。
4. **M5（可选、再确认）**：公司/研究所目录、自动shadow/canary/promotion、删除冗余旧爬虫及按实测优化。

本轮未额外触发真实新闻采集、付费LLM或邮件。长期prefork/FD/RSS压力、真实来源覆盖率/成本/容量、完整恢复和故障回滚演练仍未完成。Redis可靠性、并发硬费用/重复付费、邮件可靠交付等遗留风险按M2/M3及后续切片继续。
