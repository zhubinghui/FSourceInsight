# M1.2 Safe Fetch 本地交付

## 状态与边界

用户确认公共fetch接口及渐进接入范围后，主会话按TDD实施。保留M1.1全部未提交修改；没有子代理、SSH、真实站点/本地socket服务、付费LLM、邮件、提交、推送或部署。生产仍为M0.5。

本轮完成HTTP安全出口及RSS/HTML基类、官网入口的本地接入。**不是全来源网络收口、浏览器沙箱、确定性recipe执行器、质量门禁或完整Agent。** 计划与逐步红绿记录见 [M1.2计划](../superpowers/plans/2026-09-06-m12-safe-fetch.md)。

## 公共接口

```python
from app.crawlers.fetcher import FetchError, FetchPolicy, SafeFetcher

policy = FetchPolicy(allowed_hosts=('news.test.invalid',), max_seconds=30)
# 使用with，或者显式close；一个实例供一次同步运行复用，不跨线程/worker共享。
with SafeFetcher(policy) as fetcher:
    response = fetcher.fetch('https://news.test.invalid/news')
    body = response.body  # 有界bytes，不代表正文质量合格
    observation = response.observation  # FetchObservation
```

上述域名是示意，不在文档验证时联网执行。

- 冻结`FetchPolicy`，实例内不能替换；允许主机最多16个，精确主机匹配，无通配符、自动www或重定向扩域。
- HTTP/HTTPS仅默认80/443端口，只读GET。没有任意headers、代理、鉴权、cookies、表单或执行脚本接口。
- `fetch(url, transport='browser')`明确`render_unavailable`，没有浏览器回退。
- `FetchResponse`冻结：`body`、`observation`、`document_url`。观测有UTC时间/状态/内容类型、解压后字节数及正文SHA256标识；**标识不是已持久化快照**。304无正文/新快照，不自动证明应用层no_change。
- 观测URL去query/fragment；`document_url`保留准确最终URL以供相对链接/身份解析，且与body一样repr隐藏。不能整体asdict后写日志或交给模型；不声称原始HTML/内部URL经过秘密清洗。
- `FetchError.code/error/retryable/retry_after`提供固定分类与可选重试提示，不返回底层异常文本。目前失败不附完整HTTP观测，调用者不能凭错误猜测最终URL、状态或正文证据。
- 除既有传输码外，增加`fetch_closed`、`tls_error`、`decode_error`、`budget_exceeded`、`robots_unavailable`、`transport_unavailable`；不将拒绝、体积超限、TLS错名或robots解析错误误判成可学习的selector故障。

## 执行保障

### 连接绑定与生命周期

`fetcher.py`监督专属Python HTTP helper；`_fetch_worker.py`直接运行，不导入Flask/app。采用`sys.executable -I`、无shell、最小环境、close_fds；不继承HOME、代理/netrc路径或应用凭据。**这是HTTP实现的故障隔离，不是文件系统/容器安全沙箱。**

每次实际请求（含robots/跳转）重新检查所有DNS返回地址，任何非公网/混合私网/映射或过渡地址即拒绝。socket直接连接批准的数值IP并核对peer，不再解析主机。连接池按origin+IP区分，HTTPS保留原Host、SNI、证书域名验证；不设verify=False。公网IPv6、证书错名、DNS rebinding和peer不符均经合成网络回归。

每跳重新检查host/IP，禁止HTTPS降级、userinfo、循环及越权主机。URL在robots检查前按真实HTTP客户端规则处理dot-segment、percent encoding，并在转义后再限长；避免检查`/public/../private`后实际发送`/private`。

每实例一个绝对deadline，覆盖启动、DNS、连接/TLS、响应头/正文、robots、间隔/冷却及多次fetch。父进程非阻塞管道+selector监督；helper另设POSIX内核SIGALRM默认终止动作，避免父监督延迟/消失后DNS继续挂住。超时关闭、终止、回收helper；允许有限调度/回收/结果处理开销，不宣称实时系统零误差。支持目标为Python3.12/Linux生产及本地macOS；没有Windows验收。

Requests即使`stream=True, allow_redirects=False`也可能为了`Response.next`预读跳转正文；本实现显式关闭该路径。不排空拒绝/跳转响应，只关闭它；没有隐藏网络重试，cookies在下一请求前清空。

### 配额与HTTP数据

| 限额 | 默认/硬上界 |
|---|---|
| 实例总时限 | 默认60秒，系统policy可设到180秒 |
| 总请求 | 16，含robots、跳转、失败尝试；可收紧 |
| 单链跳转 | 5；可收紧至0 |
| 单响应压缩实体/解压实体 | 各2MiB；可收紧 |
| 实例压缩实体/解压实体 | 各8MiB；可收紧 |
| 响应协议读取 | 每响应max_wire_bytes+64KiB；实例max_total_wire_bytes+max_requests×64KiB |
| headers | 单行8KiB、最多64行，字段合计再限64KiB |
| robots正文 | 512KiB，同时受更小的policy实体配额限制 |
| 同主机间隔 | 默认0.25秒，系统可配置0–60秒，并遵守更长的Crawl-delay |

协议读取额外覆盖状态行、headers、chunk framing及trailer，避免空实体携带大量trailer绕过流量限额。字节计数不含DNS/TLS、内核/SSL缓冲预读，**不是线路计费或跨进程流量计量**。总量耗尽在下一DNS/HTTP前拒绝，不先发请求再发现没额度。

不单信Content-Length；拒绝冲突/畸形长度，按实际读取计量。支持identity/gzip，有界解压并检查EOF/尾随数据；其他编码、压缩损坏/膨胀、畸形或未允许MIME拒绝。HTML/XML/RSS/Atom/plain/JSON/JSON-LD为支持的MIME，不代表内容本身符合相应数据格式。

### robots与冷却

- 每origin在本实例内缓存规则；robots本身走同一出口/配额，无不受控重定向豁免。
- 404/410明确按缺失规则处理；401/403阻断；429/5xx保留传输失败，不默认允许；无缓存依据的304、JSON/HTML错误页、坏UTF-8/规则拒绝。
- 支持`FSourceInsightBot`专属组或`*`组、同组组合、Allow/Disallow、最长匹配、同长度Allow优先、`*`/结尾`$`、规范化路径及Crawl-delay。不是对所有非标准robots方言的兼容承诺，严格策略可能阻断原先可抓的源。
- 固定UA为`FSourceInsightBot/1.0`；不冒充浏览器绕过站点限制。
- Retry-After接受整数秒/HTTP日期，提示最多86400秒；同实例内冷却期间不再发请求。持久化/跨worker限速、共享robots缓存及超长提示处理仍需M2；没有全局冷却承诺。

## 已接入与未接入

- `RSSCrawler.fetch_articles`：scope来自source.url/feed_url明确主机；feedparser只解析bytes；保留external_id、UTC、去重和有效空feed行为。
- `HTMLCrawler.fetch_articles`：scope仅source.url；使用最终document_url解析相对链接；保留既有parse_element接口。
- `fetch_website_excerpt(url)`：scope为输入官网单主机，保留`(text, status)`、too_thin及文本长度行为；拒绝后不直连回退，日志只记固定码。
- `CrawlResult.retry_after`传播给`crawl_source`的Celery重试，避免把服务器3600秒提示丢成默认60秒；仍受既有max_retries=2约束。
- 旧RSS/HTML无已存验证器/缓存正文，收到304记失败而不是无依据no_change。FetchObservation的not_modified与应用层no_change分开。

以下文件仍含直接HTTP出口，**包括其继承/调用者均不能声称已保护**：`app/crawlers/sources/`下的`brefeco.py`、`cea_leti.py`、`esrf.py`、`french_tech_alps.py`、`inria_grenoble.py`、`ledauphine.py`、`linksium.py`、`monde_informatique.py`、`place_grenet.py`、`research_lab.py`、`soitec.py`、`stmicro.py`、`tribune_aura.py`、`usine_digitale.py`、`usine_nouvelle.py`，以及`app/crawlers/startup_discovery.py`。旧cloudscraper代码没有在本轮迁移，不属于新Safe Fetch的绕墙能力。

## 测试证据

- 不mock自己的fetcher/校验/预算函数。外部Popen包装器启动生产helper，只替换子进程DNS/socket/TLS并提供合成HTTP字节；因此测试穿过真实requests/urllib3、绑定连接、robots、解压和父子进程协议。
- 全局fixture默认阻止直接启动真实HTTP helper；只有显式网络fixture的合成bootstrap例外。父进程原有socket/DNS阻断保留，不因换成exec而失效。
- 证书名称检查使用库实际行为，但SSL握手本身是合成边界；这不是本地TLS服务、真实CA链/网络栈验收。
- DNS、headers、body阻塞均在时限终止；延迟父poll时helper以SIGALRM退出。所有测试检查helper无遗留。
- 16MiB gzip在1KiB解压上限下被拒绝，helper从DNS开始记录的Python分配峰值<2MiB；不将tracemalloc当作含所有C内存/解释器启动的RSS或生产容量测量。
- 红绿包括：初始接口缺口与非法输入、绑定/跳转/TLS、压缩与配额、robots/Retry-After；旧私网RSS实际被误入库、私网官网被当ok；304误no_change；framing/MIME错误接受；dot-segment路径偏差；慢DNS消耗间隔；巨大policy整数OverflowError。fixture错误和已存在的标准库防护单独记录，不冒充业务red。
