# LLM预留账本（M3.1a，本地实现，尚未部署）

## 保证与前提

每次通过`LLMClient`的付费尝试，先在独立数据库事务中预留，再调用供应商，最后将实际用量与结算同事务写入。串行准入使用数据库互斥行，不依赖Redis。响应缓存命中不产生新预留；fallback每次重新准入。

这是**按受信任计费契约执行的应用侧额度控制**，不是对供应商账单的无条件硬保证。管理员必须审核：

- 输入与输出单价是计费上界，覆盖该模型/端点的实际规则。
- `billing_input_limit`与`billing_output_limit`覆盖每请求全部可计费token，包括隐藏/推理token。不能填一个tokenizer估算值或典型平均值。
- 请求`max_tokens`不超过审核后的输出上界。不同供应商参数语义需人工核实。
- 存在额外固定费用、非线性/阶梯价格或无法确定token上界时，不认证该配置，不调用付费接口。

应用按两个完整上界预留，可能比较保守。缺价格/上界、非法值或账本不可用时拒绝调用；**总预算为0只取消全局金额限制，不取消计费契约检查**。不得为了绕过拒绝而把未知价格填0。

实际usage越界会记录`overrun`并阻断后续付费。对账不会自动重新认证已经被实际usage推翻的旧token上界；同provider/model/endpoint仍须配置兼容、经重新审核的上界。已发生的外部违约收费不能撤回。

## 预算日与状态

- UTC日以**预留准入时刻**确定，不以响应返回或供应商出账时刻确定。
- 当日`settled/reconciled`使用实际/人工确认费用；当日旧用量只在未链接预留时计入，避免重复收费。
- `reserved/unknown`跨日继续占用整个预留，不按TTL自动释放。
- `overrun`未处理时阻断新付费；旧用量当日无价格则拒绝新付费。迁移不伪补历史未知费用，**历史旧日志不是完整预留账本**。
- 每笔金额用Decimal向上取至微美元，不能把非零零头截成免费。
- 现有usage列`NUMERIC(10,6)`无法表示的异常大额仍保存在新账本`NUMERIC(18,6)`；旧列留NULL，不截断/溢出导致整个异常审计丢失。

状态：

| 状态 | 含义 |
|---|---|
| reserved | 已提交许可，可能在调用、崩溃，或提交确认丢失；不一定已付费 |
| settled | 有有效用量，费用已按本次固定价格结算 |
| unknown | 供应商失败或缺少/损坏用量；仍占完整额度 |
| overrun | 观察到计费token超过所声明上界，阻断新付费 |
| reconciled | 管理员依据最终供应商账单写入不可变对账记录 |

## Admin操作

1. `/admin/llm-config`编辑配置，录入价格及两个计费上界；保存时勾选已审核声明。新配置、seed和迁移均不自动认证上界。
2. `/admin/llm-usage`查看原有用量统计和新账本。用量统计不是可用余额；页面显示所有日期未决数量/金额，最多显示100行且未决优先。
3. 对账前**先确认本次执行已停止、不会继续产生收费，再核对最终账单**。仅超时、任务重试或无日志不代表未收费。
4. 填最终费用与简短账单引用，不填凭据、原始请求或完整账单正文。两项确认必须显式勾选。
5. 对账以观察到的状态作竞争检查，记录管理员/时间；重复提交不能覆盖第一次决定，旧usage不改写。未知行/非法金额/CSRF/非管理员均拒绝。
6. 存储错误只返回固定错误。提交确认丢失时先重读页面，不假定事务没提交。

对于旧版本创建、未关联预留的当日未知费用，目前没有批量自动修复入口。部署前应单独核对历史账单/切换日期，不为了继续调用而直接清空或伪填旧日志。
