## 已确认的公共 Interface

### 1. Safe Fetch

概念形状：`SafeFetcher(policy).fetch(url) -> FetchResponse`，以context manager管理连接生命周期。

- policy由系统/管理员提供并在一个运行内固定：明确允许的主机/端口、请求与字节上限、时限、robots及访问间隔；recipe和网页不能扩权。
- 成功返回有界bytes正文和M1.1的`FetchObservation`；304明确无新正文。
- 失败返回到调用方的是结构化`FetchError`（固定code/可重试性，可附合法的观测），不返回假成功或任意异常全文。
- 非HTTP(S)等非法输入无法构造正常FetchObservation：在入口拒绝，不能为了记录失败而放宽M1.1正常URL契约。
- 不提供任意请求headers/auth/cookie/proxy或表单方法；只读GET。浏览器请求在尚未支持时明确render_unavailable，不偷偷直连或绕墙。
- 多次fetch共享该实例的剩余请求/字节/时间预算；robots、跳转和尝试也消耗预算。不能每次调用都重置。跨worker/重启持久化预算和全局限速属于M2/M3，不以实例内限制冒充。

### 2. 渐进接入的既有 Interface

保持`RSSCrawler.fetch_articles`、`HTMLCrawler.fetch_articles`及`fetch_website_excerpt(url)`的调用/返回兼容；在Safe Fetch核心验收后逐条迁移其网络出口。

- RSS只把已获取bytes交给feedparser，不允许其隐式网络请求。
- 保留既有external_id/日期/去重行为；403等失败不能回退不受控requests。
- 不在此轮全量重写所有来源子类；仍有自定义直连的源明确标注未受保护。
- 单独确认源URL/feed URL/企业官网入口如何生成受控访问范围；重定向到新主机不自动扩域。

## TDD验收行为

每个行为逐项执行失败→最小修复→局部通过，不一次性写全所有用例。

1. 合法授权地址返回有界正文、最终URL和证据；连接关闭/复用行为不泄露cookie或鉴权。
2. 非HTTP(S)、userinfo、异常端口、未授权域名、IPv4/IPv6私网/本机/链路本地/映射地址均在发送HTTP前拒绝。
3. 校验DNS结果后，真实连接仍绑定已批准地址；TLS继续验证原域名、SNI及Host。不能只预查一次DNS然后让requests重新解析，也不全局monkeypatch DNS。
4. 每跳重新验证URL、域名和地址；禁止降级/私网跳转，限制跳转次数并识别循环；不透传凭据。
5. 不信任Content-Length；限制实际wire bytes和解压后bytes，拒绝压缩膨胀、损坏编码、畸形/不允许的content-type。
6. 有总deadline，而不只是connect/read timeout；包括DNS、连接/TLS、响应头/正文、robots、等待及多次请求。时限过后不得继续发请求或偷偷排队重试。
7. robots禁止则阻断；获取robots也经过同一网络校验和预算。缺失、拒绝、暂时不可用分别定义策略，不以抓取失败默认全部放行。
8. 429/5xx/超时分类、有限Retry-After/冷却、同域间隔；不触发学习，不隐藏自动重试。
9. 返回和日志不回显敏感query/凭据；超限/异常也及时释放流/连接。
10. 渐进迁移旧入口，保留原有回归；分页run循环预算由fetch实例协同，具体页序列调度仍在1.3。

## 连接与总时限细化（先记录再实现）

- 已读本机requests2.34.2/urllib3 2.7.0源码及Timeout说明：同步DNS不服从socket timeout，逐字节慢响应也能持续超过total值。不能把requests timeout直接当总deadline。
- 新增2个真实失败：父poll延迟时只有父SIGKILL（helper自身不能止住DNS），总量耗尽后仍发下一请求才报too_large。先调整执行方案：helper收到固定deadline后设置POSIX内核SIGALRM默认终止动作，父selector监督作为第二道控制；即使父不再监督，已启动fetch也到期退出。父认SIGALRM为timeout；耗尽预算在下一请求/DNS前拒绝。未做生产进程资源测量。
- 采用每个SafeFetcher运行专属的轻量Python HTTP helper进程；其中复用requests Session，父进程以有界管道协议监督同一个绝对deadline，超时终止并回收该helper，不杀业务worker。Celery prefork的daemon限制使multiprocessing子进程不合适，使用显式sys.executable/Popen、无shell。
- helper直接运行独立脚本，不导入Flask/app，不继承生产环境密钥、netrc、代理或凭据，close_fds；不是Agent或浏览器隔离的替代品。截止后仅有限回收开销，不宣称实时系统零调度误差。
- 每跳解析并检查全部DNS地址；连接类直接连接选定数值IP（不二次解析），连接池按原origin+IP区分；HTTPS保持原hostname的SNI/证书验证、原Host。Requests适配扩展要求>=2.32.2，直接使用urllib3 2.x须明确依赖范围。
- 测试通过外部Popen启动包装器给真实helper装配DNS/socket/TLS合成边界，执行生产HTTP代码，不mock自己的fetcher/校验函数；子进程也显式禁止真实网络。卡住的DNS/响应通过合成阻塞测量父进程终止/回收，不启动真实本地网络服务。
- 流量上限明确为实际读取的HTTP实体压缩前后字节，headers另设固定大小/数量限制；不将其称作含DNS/TLS/内核预读开销的线路计费。拒绝/跳转响应不排空无用正文，直接关闭连接；跳转消耗请求预算，不隐式解压正文。
- 观测URL去除query/fragment，异常只有固定码；为避免破坏含query的相对链接/身份解析，FetchResponse.document_url保留准确最终地址但repr隐藏，仅供应用解析。禁止将整个response/asdict直接写日志或交给模型；并不承诺原始HTML/内部解析字段经过秘密清洗。
- 初始实例上限：60秒/16请求/5跳转，单响应压缩与解压实体2MiB、全实例各8MiB、同主机间隔0.25秒；robots最大512KiB。系统policy可以收紧，不能由recipe覆盖。跨实例全局预算/限速仍待M2/M3。
