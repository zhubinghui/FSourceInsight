  `company_refresh_job` rows instead. Manual *AI Refresh* uses the same jobs. New task module
  `app.llm.refresh_tasks` and a 60-second recovery beat entry.
- Web: company page shows the latest refresh state; date filters include the whole day; weekly trend fixed;
  revision history and merge aliases persist.

- Migration `d3e7a1c95b28`: one new table and a nullable `llm_reservation.company_refresh_id`. Expand-only;
  old code keeps working on the new schema, which is what makes image rollback safe.

Delta versus `a93beb8`: `app/`, `celery_app.py`, one migration, docs, tests. No `requirements/`, `docker/` or
Compose change, so the cached pip layer is reused. The script refuses to continue if any dependency differs.

## Script steps (`~/.cache/fsi-release/m34c_release.sh`, run on the VPS with the expected head as argument)

1. Take the release lock. Require a clean checkout at `a93beb8`, the four apps on the ner images, `origin/master`
   equal to the expected head and containing the running commit, and no infra paths in the delta.
   Then fast-forward the checkout.
2. Build the four images while the old containers run and tag them `candidate-<tag>`. Compare `pip freeze` and
   Python version with each running container; any difference aborts. Write a new pin layer copied from the ner
   layer with only the images replaced, asserting every other field is identical. The candidate must report head
   `d3e7a1c95b28`.
3. Record ledger state: reservation counts and amounts by state, and today's usage rows.
4. Stop beat. Wait until the llm and fast workers report no active or reserved tasks, up to 10 minutes. Record
   queue lengths. Stop the workers with a 180-second grace period, then stop web.
5. Take a full `mysqldump` inside the MySQL container using its own environment, into a 0700 directory as a 0600
   file. Verify gzip integrity, the completion trailer and the SHA-256.
6. Run `flask db upgrade` from the candidate image. Require current `d3e7a1c95b28 (head)`, an empty
   `company_refresh_job` table and the new column.
7. Start web and both workers from the new pin layer. Wait for local health. Require the llm worker to register
   `app.llm.refresh_tasks.refresh`. Start beat last.
8. Record the ledger again and require it unchanged. Show images, restart counts, public health and error lines
   from the last minutes.

If anything fails after step 4 stops services, the script restarts all four apps from the ner pin layer. The
additive schema stays; the old code ignores it. It never restores the database automatically.
